## §2.3 partial reads: PBT-Bench, SysMoBench, TLA+-Bench, Req2LTL, Gay et al., Mäder & Egyed

### Takeaway
All six figures exist in their sources, but four need correcting or qualifying:
- **PBT-Bench**: the stop-after-one-bug finding holds for one model (Opus 4.8) under one prompt, and one instruction removes it.
- **SysMoBench**: only one LLM (Claude-Sonnet-4) reached the conformance phase on Etcd Raft at all.
- **TLA+-Bench**: the probe, as worded, cannot detect what it claims to detect (*Inference*).
- **Gay et al.**: "up to 40.6%" is the authors' introduction figure. Their own Table 4 shows up to −59.2%, and the gap appears only on 4 of the 7 systems.

Req2LTL's "inconsistency" is resolved: two metrics are applied to two different datasets. Mäder & Egyed stays unverifiable at full-text level; only a 2-page author summary was reachable.

### Cited Findings

**PBT-Bench (arXiv 2605.15229 v4, full text read, 27 pp)**
- Setting: "100 curated property-based testing problems across 40 real Python libraries. Each problem injects one or more semantic bugs (365 in total, mean 3.65 per problem)". Eight LLMs × two prompt regimes × 3 runs = 4,800 trajectories. Claude Opus 4.8 was added post-review, both in OpenHands and in Claude Code. — [PBT-Bench](https://arxiv.org/abs/2605.15229), abstract and §5
- How a bug counts as found (§4 Evaluation): a test function "is useful for bi if it fails on the buggy version and passes after bi is reversed. The bug is found if at least one function is useful for it." Recall is "bugs_found/bugs_total averaged over problems". — [PBT-Bench](https://arxiv.org/abs/2605.15229) §4
- Table 1(a), PBT mode: recall ranges from Grok 4.1 Fast 42.1% ± 4.3 to Sonnet 4.6 83.4% ± 3.3. Opus 4.8 scores 81.2%, and 78.6% in Claude Code. "No configuration finds all bugs on more than 67% of problems." — [PBT-Bench](https://arxiv.org/abs/2605.15229) Table 1, §5.1
- The single-bug behaviour is specific to Opus 4.8 under the Baseline prompt: "under the open-ended Baseline prompt ('write a test that fails'), Opus 4.8 stops after exposing one bug. It writes a median of two test functions per problem (Sonnet 4.6: eight), finds at least one bug on 97% of problems, yet finds all bugs on only 12%." Baseline recall is 39.3%. — [PBT-Bench](https://arxiv.org/abs/2605.15229) §5.1, Table 1(b)
- Ablation (Table 2): for Opus 4.8, the framework-only prompt, which includes "cover the specification rather than hunt for one bug", adds +41.5 pp [+34.2, +47.7] over Baseline. The taxonomy and template add +0.2 pp. For DeepSeek V3.2, framework-only is −14.4 pp versus Baseline (22% of its runs produced no test file). — [PBT-Bench](https://arxiv.org/abs/2605.15229) Table 2, §6.1
- Venue: the arXiv comment says "Accepted at NeurIPS 2026, Evaluations & Datasets Track (poster)". An OpenReview v2 search found no record. — [arXiv API record](https://export.arxiv.org/api/query?id_list=2605.15229)

**SysMoBench (arXiv 2509.23130 v3, full text read, 37 pp; Table 3 checked against a rendered image of p. 9)**
- Table 3(a), Asterinas Spinlock: conformance is 100/80/80/80% for basic modelling and 100% for all four LLMs with code translation. — [SysMoBench](https://arxiv.org/abs/2509.23130) Table 3, p. 9
- Table 3(b), Etcd Raft:
  - Basic modelling: Claude-Sonnet-4 reached syntax 100%, runtime 25.00%, **conformance 7.69%**, invariant 69.23%. GPT-5, Gemini-2.5-Pro and DeepSeek-R1 failed syntax (47.87–50.00%, ✗), so they got no conformance score.

  - Source: [SysMoBench](https://arxiv.org/abs/2509.23130) Table 3, p. 9
- The metric: "we define Mc as the coverage of code actions without conformance errors: Mc = nc/nt, where nc is the number of code actions that were covered during validation with no errors, and nt is the total number of actions in the instrumented code." — [SysMoBench](https://arxiv.org/abs/2509.23130) §3.2.3
- "few AI-generated models achieved fine-grained conformance" — [SysMoBench](https://arxiv.org/abs/2509.23130) §3.2.4

  - "In our experience, state-of-the-art LLMs accomplish the mapping task reliably" (§3.2.3).
  - "We inspected the LLM-assisted mapping and concretization, and found the results to be correct.   - No count of inspected mappings and no error rate is given. — [SysMoBench](https://arxiv.org/abs/2509.23130) §3.2.3, §4
- Setup: 11 artefacts ("eleven diverse system artifacts"); three agents (basic modelling, code translation, trace learning), with the trace-learning results omitted because it "fails to pass runtime checks"; four LLMs; best of five runs; three repair iterations. — [SysMoBench](https://arxiv.org/abs/2509.23130) abstract, §4, §5

**TLA+-Bench (arXiv 2607.23425 v1, full text read, 17 pp)**
- Exact probe wording (§8.7): "The mutation test asks whether the checked property is loadbearing. For each passing output we replace every checked safety invariant named by the configuration with the literal TRUE and re-run TLC. When the configuration checks a temporal property rather than a mutable safety invariant, the test does not apply and the pass is scored as non-surviving, so the test is a lower bound on vacuity. Of the 30 passes, 12 … check a temporal property with no mutable safety invariant and are scored non-surviving on that ground, while 18 name a safety invariant the test can act on. A pass survives when the mutated run still fails, which shows the property genuinely constrains behavior. A pass whose mutated run then succeeds was vacuous. 5 of the 18 testable passes survive … Counted against all 300 outputs this is 5 of 300, the 1.7% envelope bound; because the 12 temporal-only passes are scored against the rate rather than excluded, that 1.7% is a conservative lower bound rather than a direct vacuity measurement." — [TLA+-Bench](https://arxiv.org/pdf/2607.23425) §8.7
- The 300 outputs are "one fixed set of 300 outputs" pooled over three frontier models on 100 specs. The default regime gives 10.0% (30/300) and the substantive regime 12/30 passes. — [TLA+-Bench](https://arxiv.org/pdf/2607.23425) §8.2, Table 5

Evaluating Natural-Language-to-TLA+ Generation" (ICSOFT 2026, DOI 10.5220/0015070400004088). - Setting: "we generate tests for seven industrial critical systems—four Rockwell Collins systems from previous work, a NASA system, as well as two subsystems of a complex real-time infusion pump". The coverage criteria are condition, decision, MC/DC and OMC/DC. Effectiveness was measured "through mutation analysis—and, for two systems, a set of real faults" (7 real faults in Infusion Mgr, 3 in Alarms). For the NASA example and the two infusion pump systems … and the Observable MC/DC (OMC/DC) criterion … test suites generated to satisfy structural coverage—performed better, matching or improving on randomly generated test suites of the same size." — [Gay et al. preprint](https://www.greggay.com/pdf/15covrisks.pdf) §1

- Real faults, Infusion Mgr, OO: "% of tests failed" is −63.8% (condition, Table 7), −80.2% (decision, Table 8) and −93.4% (MC/DC, Table 9). This is a different metric. — [Gay et al. preprint](https://www.greggay.com/pdf/15covrisks.pdf) Tables 7–9

### Inferences
- *Inference*: PBT-Bench's single-bug failure is a property of the prompt, and a one-sentence coverage instruction removes it for the model concerned. That supports the earlier report's structural remedy (the harness imposes one obligation per clause). It does not support a claim that agents generally cannot cover a spec.
- *Inference*: SysMoBench's Mc values of 7.69% and 15.38% equal 1/13 and 2/13. This suggests about 13 instrumented code actions in Etcd Raft, so each figure rests on one or two actions. The paper does not state nt for Etcd Raft.
- *Inference*: replacing a safety invariant with TRUE removes that check, so TLC can then fail only for other reasons, such as deadlock, other configured properties or errors. The paper's survival criterion ("the mutated run still fails") therefore does not, as written, show that the invariant constrains behaviour. The usual vacuity probe works the other way round: mutate the model or the invariant to something falsifiable and require a counterexample, as TLA-Prover's Diamond tier does. Either the wording is garbled or the probe measures something else. The 5/18 and 1.7% figures are the paper's own counts and cannot be read as a vacuity rate.
- *Inference*: Req2LTL's 88.4% means "two experts agreed it is semantically equivalent to a gold formula", not string identity. No automatic equivalence check (e.g. Spot language equivalence) was used, although Spot was used for syntax. The paper does not say whether judges were blind to the method.

- PBT-Bench's NeurIPS acceptance is not confirmed outside the authors' arXiv comment.
