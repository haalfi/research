## fetch:docs.databricks.com None None
 - Databricks' deployment guide (documented) describes an optional landing zone where raw files arrive from external systems before bronze ingestion. It recommends Unity Catalog volumes for that landing step. This supports the landing-files-first pattern (Q3, Q0 Option B), but the guide does not say directly that API payloads should be landed rather than written straight to bronze. | Use Unity Catalog volumes for landing raw data before bronze ingestion.
 - The guide (documented) says larger organisations often run a separate cloud landing zone that receives raw files from external systems before bronze. It presents this as common practice, not a requirement. | Pipelines in larger organizations often have an additional landing zone in the cloud.
 - The guide recommends Auto Loader, inside Lakeflow pipelines, for file ingestion from cloud storage, and event-notification triggers to start ingestion pipelines (documented). It does not cover file-arrival trigger storage requirements, checkpoints or replay. | Use Auto Loader for efficient file ingestion from cloud storage.
 - The guide (documented) defines bronze as an append-only source of truth that holds raw data exactly as it arrives, so later layers can be rebuilt from it. This bears on whether writing parsed payloads straight to bronze keeps the 'raw as arrived' property. That it may not is inference. | Source of truth: Raw data exactly as it arrives from source systems.
 - The guide (documented) recommends idempotent, incremental ingestion so retries are handled safely. It does not mention API ingestion by custom jobs at all. It points to Lakeflow Connect, or tools such as Fivetran, for external sources. | Implement idempotent ingestion to handle retries safely.
