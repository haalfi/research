## 2. How vendors define "the harness" and its boundaries

### Takeaway
Two converging definitions emerge. LangChain says the harness is "everything that isn't the model". Anthropic says it is "the loop that calls Claude and routes Claude's tool calls" and keeps it distinct from the session (durable log) and the sandbox (execution). The vendors also share a meta-claim: each harness component encodes an assumption about what the model can't do, so harnesses should shrink as models improve.

### Cited Findings
- **Anthropic** names three virtualized components: "a session (the append-only log of everything that happened), a harness (the loop that calls Claude and routes Claude's tool calls to the relevant infrastructure), and a sandbox (an execution environment where Claude can run code and edit files)". It adds: "We're opinionated about the shape of these interfaces, not about what runs behind them." [Established] — [Anthropic Managed Agents, Apr 2026](https://www.anthropic.com/engineering/managed-agents)
- **Anthropic**: "brain" = "Claude and its harness". "Hands" = "sandboxes and tools that perform actions". "Session" = "the log of session events". Managed Agents is called "a meta-harness … unopinionated about the specific harness that Claude will need". [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- **Anthropic** on evals: "An agent harness (or scaffold) is the system that enables a model to act as an agent: it processes inputs, orchestrates tool calls, and returns results. When we evaluate 'an agent,' we're evaluating the harness and the model working together." This is distinct from an "evaluation harness", the infrastructure that runs evals end-to-end. [Established] — [Anthropic, Demystifying evals, Jan 2026](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)
- **Anthropic** calls the Claude Agent SDK "a powerful, general-purpose agent harness" with "context management capabilities such as compaction". [Established] — [Anthropic, Effective harnesses, Nov 2025](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- **LangChain**: "Agent = Model + Harness … If you're not the model, you're the harness. A harness is every piece of code, configuration, and execution logic that isn't the model itself." Listed contents: system prompts; tools, skills, MCPs and their descriptions; bundled infrastructure (filesystem, sandbox, browser); orchestration logic (subagent spawning, handoffs, model routing); and hooks/middleware for deterministic execution (compaction, continuation, lint checks). [Established] — [LangChain, Anatomy of an Agent Harness, Mar 2026](https://blog.langchain.com/the-anatomy-of-an-agent-harness/)
- **LangChain** names the harness "knobs" as "system prompts, tools, hooks/middleware, skills, sub-agent delegation, memory systems". [Established] — [LangChain, Improving Deep Agents, Feb 2026](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering)
- **Anthropic, building block**: the "augmented LLM", an LLM "enhanced with augmentations such as retrieval, tools, and memory". Workflows are "LLMs and tools … orchestrated through predefined code paths"; agents "dynamically direct their own processes and tool usage". [Established] — [Anthropic BEA](https://www.anthropic.com/engineering/building-effective-agents)
- **Anthropic** later simplified the agent definition to "LLMs autonomously using tools in a loop". [Established] — [Anthropic context engineering, Sep 2025](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- **OpenAI**: an agent "leverages an LLM to manage workflow execution and make decisions … recognizes when a workflow is complete … can halt execution and transfer control back to the user", and it uses tools "always operating within clearly defined guardrails". The foundations are Model, Tools and Instructions. The single-agent diagram labels "Instructions, Tools, Guardrails, Hooks". [Established] — [OpenAI practical guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- **Meta-principle (Anthropic)**: "harnesses encode assumptions about what Claude can't do on its own … those assumptions … can go stale as models improve". Example given: context resets added for Sonnet 4.5's "context anxiety" "had become dead weight" on Opus 4.5. [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents); repeated as "every component in a harness encodes an assumption about what the model can't do on its own, and those assumptions are worth stress testing" — [Anthropic harness design, Mar 2026](https://www.anthropic.com/research/harness-design-long-running-apps)
- **Manus** frames its bet as context engineering over training an end-to-end model: "If model progress is the rising tide, we want Manus to be the boat, not the pillar stuck to the seabed." It reports "rebuilt our agent framework four times". [Established] — [Manus, Jul 2025](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- **LangChain** says models and harnesses are now co-trained: "Claude Code and Codex are post-trained with models and harnesses in the loop". It also argues the post-training harness is not necessarily the best harness (Terminal Bench 2.0 example). [Established, claim] — [LangChain Anatomy](https://blog.langchain.com/the-anatomy-of-an-agent-harness/)

### Inferences
- [Synthesized] Two scopes of "harness" coexist. The **narrow** one (Anthropic Managed Agents) is the loop plus routing plus context transformation, with storage (session) and execution (sandbox) excluded. The **broad** one (LangChain; Anthropic evals) is everything that isn't the model, sandbox and filesystem included. A framework should state which scope it uses.
- [Inference] The "harness shrinks as models improve" principle implies a responsibility taxonomy should separate durable interfaces (session, sandbox, tool contract) from model-compensating scaffolding (resets, sprints, todo-recitation). Only the latter is expected to be deleted over time.

### Gaps
- No vendor publishes a formal, versioned interface spec for a harness beyond the function signatures in the Managed Agents post.

## 3. Mechanisms per responsibility (hypothesis: Loop, Tools, Context, Memory, Control)

### Takeaway
All five hypothesized responsibilities appear across sources, and each has concrete mechanisms. Durable execution/state, observability/tracing, evaluation/verification, sandboxing/execution isolation, and multi-agent orchestration recur often enough, with distinct mechanisms, to warrant their own categories or explicit sub-categories. The weakest boundary is Context vs Memory: vendors treat filesystem notes, compaction and sub-agents as both.

### Cited Findings

**Loop (control flow, termination, workflow patterns)**
- Five workflow patterns plus autonomous agents: prompt chaining (with programmatic "gate" checks), routing, parallelization (sectioning, voting), orchestrator-workers, and evaluator-optimizer. Agents are "LLMs using tools based on environmental feedback in a loop". [Proposed, from customer experience] — [Anthropic BEA](https://www.anthropic.com/engineering/building-effective-agents)
- Termination: "The task often terminates upon completion, but it's also common to include stopping conditions (such as a maximum number of iterations)". Agents "pause for human feedback at checkpoints or when encountering blockers". [Proposed] — [Anthropic BEA](https://www.anthropic.com/engineering/building-effective-agents)
- OpenAI's "run" is "a loop that lets agents operate until an exit condition is reached. Common exit conditions include tool calls, a certain structured output, errors, or reaching a maximum number of turns". `Runner.run()` loops until a final-output tool is invoked or the model returns a response without tool calls. [Established, SDK behaviour as documented] — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Manus loop: the model selects an action from a predefined action space, the action executes in a VM sandbox, and the observation is appended to context; average about 50 tool calls per task. [Established] — [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- "Ralph Loop": a hook intercepts the model's exit attempt and "reinjects the original prompt in a clean context window", with state carried via the filesystem. [Established, as described] — [LangChain Anatomy](https://blog.langchain.com/the-anatomy-of-an-agent-harness/)
- Loop pathology control: `LoopDetectionMiddleware` tracks per-file edit counts via tool-call hooks and injects "consider reconsidering your approach" after N edits, to break "doom loops" (seen 10+ times in some traces). [Established] — [LangChain Improving Deep Agents](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering)
- Reasoning-budget scheduling: an "xhigh-high-xhigh 'reasoning sandwich'" (plan / build / verify). [Established] — [LangChain Improving Deep Agents](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering)
- Long-running loop structure: an initializer agent (writes init.sh, claude-progress.txt, an initial git commit and a feature_list.json of 200+ features, all marked failing), then coding agents that do one feature per session. [Established] — [Anthropic Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- Later variant: planner → generator (sprints) → evaluator, with a negotiated "sprint contract" per sprint and inter-agent communication through files. With Opus 4.6, the sprints were removed and the evaluator moved to a single end pass. [Established] — [Anthropic harness design](https://www.anthropic.com/research/harness-design-long-running-apps)

**Tools (definition design, execution, sandboxes, code execution, computer use)**
- The agent-computer interface (ACI): invest in it as much as in HCI. Choose formats close to internet text, avoid escaping and line-count overhead, include examples and edge cases, and poka-yoke arguments. [Proposed] — [Anthropic BEA, Appendix 2](https://www.anthropic.com/engineering/building-effective-agents)
- Tool design principles: a few high-impact workflow tools (e.g. `search_contacts` rather than `list_contacts`); namespacing by service/resource (prefix vs suffix has "non-trivial effects" in evals); return meaningful context; a `response_format` enum ("concise" vs "detailed"; example 72 vs 206 tokens, about ⅓); pagination, range selection, filtering and truncation; Claude Code caps tool responses at 25,000 tokens by default; prompt-engineer error messages. [Established] — [Anthropic Writing tools, Sep 2025](https://www.anthropic.com/engineering/writing-tools-for-agents)
- OpenAI's split guideline: "Some implementations successfully manage more than 15 well-defined, distinct tools while others struggle with fewer than 10 overlapping tools." [Established, anecdotal] — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Uniform tool interface for execution environments: `execute(name, input) → string`. It covers containers, custom tools and MCP servers; "The harness doesn't know whether the sandbox is a container, a phone, or a Pokémon emulator." Containers are provisioned lazily via `provision({resources})`. [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- Tool availability by masking: rather than adding or removing tools mid-loop (which invalidates the KV-cache and confuses the model), Manus uses a "context-aware state machine" that masks token logits. It uses Auto / Required / Specified function-calling prefill modes and consistent name prefixes (`browser_`, `shell_`). [Established] — [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Contrasting approach: "apply RAG … to tool descriptions in order to fetch only the most relevant tools". [Established, as surveyed] — [LangChain Context Engineering](https://blog.langchain.com/context-engineering-for-agents/). Manus reports trying RAG-like dynamic tool loading and advises against it "unless absolutely necessary" — [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Skills as packaged procedural tools/knowledge: a directory with SKILL.md (YAML name + description pre-loaded into the system prompt), with bundled scripts executed via code execution because "sorting a list via token generation is far more expensive than simply running a sorting algorithm". [Established] — [Anthropic Agent Skills, Oct 2025](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- Bash/code as a general-purpose tool; sandboxes for "secure, isolated execution"; allow-listed commands and network isolation; environments created on demand. [Proposed] — [LangChain Anatomy](https://blog.langchain.com/the-anatomy-of-an-agent-harness/)
- OpenAI tool categories: data, action and orchestration (agents as tools). [Established] — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Computer use: listed only as an example agent (Anthropic's "computer use" reference implementation). Browser automation (Puppeteer MCP, Playwright MCP) is used as the verification tool. [Established] — [Anthropic BEA](https://www.anthropic.com/engineering/building-effective-agents); [Anthropic Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

**Context (assembly, compaction, retrieval, JIT, isolation, caching)**
- Context engineering: "the smallest possible set of high-signal tokens". Context rot and "attention budget". System prompt at the "right altitude". Minimal, non-overlapping tool sets. Canonical few-shot examples. [Proposed] — [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Just-in-time retrieval via lightweight identifiers (paths, queries, links) plus progressive disclosure. Hybrid approach in Claude Code: CLAUDE.md is loaded up front, and glob/grep run just-in-time. [Established] — [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Compaction (Claude Code: summarize, then continue with the summary plus the 5 most recently accessed files). Tool-result clearing is "one of the safest lightest touch forms of compaction". Tune compaction prompts by maximizing recall first, then precision. [Established] — [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Context reset vs compaction: a reset "clear[s] the context window entirely and start[s] a fresh agent", with a handoff artifact. Compaction keeps continuity but "doesn't give the agent a clean slate". [Established] — [Anthropic harness design](https://www.anthropic.com/research/harness-design-long-running-apps)
- Four strategy buckets: write, select, compress, isolate. Claude Code "auto-compact" fires at 95% of the window. Isolation via sub-agents, sandboxes (HF CodeAgent) or runtime state-object fields. [Established, as surveyed] — [LangChain Context Engineering, Jul 2025](https://blog.langchain.com/context-engineering-for-agents/)
- Tool-call offloading: keep the head and tail of large outputs and offload the full output to the filesystem. [Established] — [LangChain Anatomy](https://blog.langchain.com/the-anatomy-of-an-agent-harness/)
- KV-cache-centred design: the KV-cache hit rate is "the single most important metric for a production-stage AI agent". Input:output about 100:1. Cached vs uncached Sonnet tokens $0.30 vs $3/MTok. Keep the prefix stable (no timestamps), make context append-only, use deterministic JSON serialization, add explicit cache breakpoints. [Established] — [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Restorable compression: drop page content but keep the URL; drop document content but keep the path. Attention steering by "recitation" (todo.md rewritten at the end of the context). Keep errors in context. Avoid few-shot ruts by adding structured variation. [Established] — [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Claude Code's todo tool "is basically a no-op … just context engineering strategy". [Established, LangChain's characterization] — [LangChain Deep Agents, Jul 2025](https://blog.langchain.com/deep-agents/)
- Session-as-context-object: `getEvents()` gives "positional slices of the event stream". Fetched events "can also be transformed in the harness before being passed to Claude's context window", including for "a high prompt cache hit rate". [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- Skills' three-level progressive disclosure: metadata in the system prompt → SKILL.md body → bundled files. The bundleable context is "effectively unbounded". [Established] — [Anthropic Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- Compression model: a dedicated LLM compresses history into "key details, events, and decisions". Cognition fine-tuned a smaller model for this. [Established, claim] — [Cognition](https://cognition.ai/blog/dont-build-multi-agents)

**Memory (sessions, progress files, checkpoints, memory tools, external stores)**
- Structured note-taking / agentic memory (NOTES.md, to-do lists, the Pokémon example). A memory tool (public beta at the Sonnet 4.5 launch) for a "file-based system" outside the context. [Established] — [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Progress artifacts across sessions: claude-progress.txt, git history, and feature_list.json. JSON is chosen because "the model is less likely to inappropriately change or overwrite JSON files compared to Markdown". A get-your-bearings routine: pwd → progress → features → git log → init.sh → smoke test. [Established] — [Anthropic Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- The lead agent saves its plan to Memory because "if the context window exceeds 200,000 tokens it will be truncated". Agents "summarize completed work phases and store essential information in external memory". [Established] — [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)
- The filesystem as "the ultimate context … unlimited in size, persistent by nature, and directly operable by the agent". [Established] — [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- AGENTS.md-style memory files are injected at start and edited by agents, framed as "a form of continual learning". [Established] — [LangChain Anatomy](https://blog.langchain.com/the-anatomy-of-an-agent-harness/)
- Memory types (procedural, episodic, semantic) with embedding/knowledge-graph selection. The selection-failure example is ChatGPT injecting a user's location. [Established, as surveyed] — [LangChain Context Engineering](https://blog.langchain.com/context-engineering-for-agents/)
- Session log as durable memory: append-only, written via `emitEvent(id, event)` and read via `getSession(id)` / `getEvents()`. [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)

**Control (permissions, guardrails, HITL, hooks, budgets)**
- Layered guardrails: relevance classifier, safety classifier (jailbreak/prompt injection), PII filter, moderation, tool safeguards, rules-based protections (blocklists, input length limits, regex), and output validation. "Optimistic execution": guardrails run concurrently and raise a tripwire exception. [Proposed] — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Tool risk rating: low / medium / high, by read vs write, reversibility, permissions and financial impact. The rating triggers pauses or escalation. [Proposed] — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Human intervention triggers: "Exceeding failure thresholds" (retry/action limits) and "High-risk actions" (cancel orders, large refunds, payments). [Proposed] — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Parallel guardrail call: "one model instance processes user queries while another screens them", which "tends to perform better than having the same LLM call handle both". [Proposed] — [Anthropic BEA](https://www.anthropic.com/engineering/building-effective-agents)
- Effort budgets in prompts: 1 agent with 3–10 tool calls for simple fact-finding; 2–4 subagents with 10–15 calls each for comparisons; more than 10 subagents for complex research. [Established] — [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)
- Credential isolation as a structural control: tokens are "never reachable from the sandbox". Git tokens are wired in at sandbox init. MCP OAuth tokens sit in a vault and are used via a proxy. "The harness is never made aware of any credentials." [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- Hooks/middleware "for deterministic execution (compaction, continuation, lint checks)". Hooks can run test suites after each step. [Proposed] — [LangChain Anatomy](https://blog.langchain.com/the-anatomy-of-an-agent-harness/)
- Prompt-level control on artifacts: "It is unacceptable to remove or edit tests". [Established] — [Anthropic Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- Skill supply-chain risk: install only from trusted sources and audit bundled code. [Proposed] — [Anthropic Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)

**Candidate extra responsibilities**
- *Durable execution*: "we need to durably execute code and handle errors … built systems that can resume from where the agent was … deterministic safeguards like retry logic and regular checkpoints". "Rainbow deployments" protect running agents during updates. [Established] — [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system). A harness crash is recovered via `wake(sessionId)` + `getSession(id)` and resume from the last event; a container failure surfaces as a tool error and the container is re-provisioned. [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents). Temporal splits the work into deterministic Workflow code (orchestration) and non-deterministic Activities (LLM calls, tools, MCP client). On a crash the Workflow "replays" from Event History using recorded LLM decisions, so there is "No re-analysis. No different decisions". [Established, vendor claim] — [Temporal, Nov 2025](https://temporal.io/blog/of-course-you-can-build-dynamic-ai-agents-with-temporal); human approval steps are modelled inside Workflows — [Temporal, Jul 2025](https://temporal.io/blog/durable-execution-meets-ai-why-temporal-is-the-perfect-foundation-for-ai)
- *Observability/tracing*: "Adding full production tracing let us diagnose why agents failed". Anthropic monitors "decision patterns and interaction structures" without monitoring conversation contents. [Established] — [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system). LangSmith traces are analyzed by a "Trace Analyzer Skill" to drive harness changes. [Established] — [LangChain Improving Deep Agents](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering). The coupled-container design made failures indistinguishable ("a bug in the harness, a packet drop … or a container going offline all presented the same"), which motivated decoupling. [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- *Evaluation/verification*: vocabulary of task, trial, grader (code-based, model-based, human), transcript and outcome; graders on the transcript vs the outcome. [Established] — [Anthropic Demystifying evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents). Start with about 20 queries; use an LLM-as-judge rubric (factual accuracy, citation accuracy, completeness, source quality, tool efficiency); evaluate the end state for state-mutating agents. [Established] — [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system). Tool evals use simple while-loops, held-out test sets, and metrics such as runtime, number of calls, tokens and errors. [Established] — [Anthropic Writing tools](https://www.anthropic.com/engineering/writing-tools-for-agents). In-loop verification: a separate evaluator agent with Playwright, calibrated with few-shot score breakdowns. "Out of the box, Claude is a poor QA agent." [Established] — [Anthropic harness design](https://www.anthropic.com/research/harness-design-long-running-apps). Build-and-self-verify middleware. [Established] — [LangChain Improving Deep Agents](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering)
- *Sandboxing*: the sandbox is a first-class component ("cattle", provisioned on demand, credential-free). [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents). "Extensive testing in sandboxed environments". [Proposed] — [Anthropic BEA](https://www.anthropic.com/engineering/building-effective-agents)
- *Multi-agent orchestration*: OpenAI offers the manager pattern (agents as tools) and the decentralized pattern (handoffs: a one-way transfer that carries the conversation state). Its advice is to "maximize a single agent's capabilities first". [Established/Proposed] — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf). Anthropic uses orchestrator-worker with synchronous subagents; subagents write to the filesystem and pass references back to avoid a "game of telephone". [Established] — [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)

### Inferences
- [Synthesized] Verdict on the hypothesis:
  - **Loop**: confirm. Every source has it. Sub-mechanisms are exit conditions, turn caps, workflow patterns, continuation hooks and loop detection.
  - **Tools**: confirm, but consider splitting off **Execution environment/sandbox**. Anthropic treats the sandbox as a separate component behind the tool interface, and LangChain lists it as "bundled infrastructure".
  - **Context**: confirm. It has the richest mechanism set across 6+ sources.
  - **Memory**: confirm, but redefine it as *persistent state outside the context window* (session log, files, git, memory tool). Vendors use the same artifacts (files, notes) for both context management and memory, so the framework should define Memory as the store and Context as the per-turn selection or projection from it. That follows Anthropic's session-vs-harness split.
  - **Control**: confirm, but its mechanisms are of two kinds: *safety/permission* (guardrails, risk ratings, credential isolation, HITL) and *budget/steering* (turn limits, effort scaling, reasoning budgets, loop detection). A split or sub-heading is warranted.
  - **Add**: Durable execution/state recovery (Anthropic MA, Anthropic research, Temporal), Observability (Anthropic research, LangChain), Verification/Evaluation (in-loop evaluator agents vs offline evals; vendors treat both as harness concerns), and Orchestration/multi-agent (OpenAI, Anthropic, Cognition).
- [Inference] "Hooks/middleware" is a *mechanism* that cuts across categories (compaction, continuation, lint, loop detection, guardrails), not a responsibility.

### Gaps
- Permission models (allow/deny rules, approval modes) as harness mechanisms are thinly documented in these engineering posts. They likely live in product docs (Claude Code, Codex, Agents SDK), which this track did not fetch.
- OpenAI's own harness-engineering account is Unreachable, so OpenAI-side mechanisms come only from the 2025 PDF guide.

## 4. Recommended architectural boundaries and interfaces

### Takeaway
Anthropic's Managed Agents post is the most explicit reference architecture. It has three interfaces: session (durable append-only log, source of truth), harness (stateless, replaceable loop and context transformer) and sandbox/tools (cattle behind `execute(name, input) → string`), with credentials kept outside the sandbox. Temporal's deterministic-workflow / non-deterministic-activity split is a structurally similar durable-execution boundary.

### Cited Findings
- Interfaces named: `execute(name, input) → string`, `provision({resources})`, `wake(sessionId)`, `getSession(id)`, `emitEvent(id, event)`, `getEvents()`. "Each became an interface that made few assumptions about the others, and each could fail or be replaced independently." [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- "The session is not Claude's context window." Storage is separate from context management: "recoverable context storage in the session and arbitrary context management in the harness", because "we can't predict what specific context engineering will be required in future models". [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- The harness is stateless: "nothing in the harness needs to survive a crash", and "Scaling to many brains just meant starting many stateless harnesses". [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- OS analogy: virtualize components the way OSes virtualized hardware (process, file), designing for "programs as yet unthought of". [Proposed] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- The security boundary is between generated code and credentials. A vault plus an MCP proxy hold the tokens, so the harness never sees them. [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- "Many brains, many hands": "brains can pass hands to one another". [Established] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- Temporal: "Workflow is the orchestration layer … needs to be deterministic"; "Activities are where the actual work happens: calling LLMs, invoking tools". Event History serves as the record for replay. [Established, vendor claim] — [Temporal, Nov 2025](https://temporal.io/blog/of-course-you-can-build-dynamic-ai-agents-with-temporal)
- Manus: an append-only context with a stable prefix, treated as an invariant for the cache; tools are masked, not removed. [Established] — [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- The filesystem as a coordination boundary between agents ("a shared ledger of work") and between subagents and the coordinator (artifact references instead of copied content). [Established] — [LangChain Anatomy](https://blog.langchain.com/the-anatomy-of-an-agent-harness/); [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)
- Workflows (predefined code paths) vs agents (model-directed) as the primary architectural choice: "find the simplest solution possible". [Proposed] — [Anthropic BEA](https://www.anthropic.com/engineering/building-effective-agents)

### Inferences
- [Synthesized] Anthropic's session log and Temporal's Event History play the same role: an append-only source of truth from which a replaceable executor resumes. They differ in what happens on resume. Temporal replays recorded LLM outputs deterministically. Anthropic's harness reads events and lets the model continue, and it allows arbitrary re-projection of the log into context.
- [Inference] Manus's append-only context and Anthropic's append-only session share the "never mutate history" principle, but for different reasons: cache economics for Manus, recoverability for Anthropic.

### Gaps
- No vendor reports a head-to-head comparison of these boundary choices (e.g. coupled vs decoupled) on task quality. The only reported effect is latency (section 6).

## 5. Where vendors disagree

### Takeaway
The clearest disagreement is single vs multi-agent. Cognition argues by default against parallel subagents lacking shared context. Anthropic reports large gains from orchestrator-worker research agents but concedes that coding is a poor fit. OpenAI says maximize a single agent first. Smaller disagreements concern dynamic tool loading and compaction vs reset vs restorable offloading.

### Cited Findings
- Cognition: "Share context, and share full agent traces, not just individual messages" and "Actions carry implicit decisions, and conflicting decisions carry bad results". It would "by default rule out any agent architectures that don't abide by them". The recommended default is a "single-threaded linear agent", plus a history-compression model for long tasks. It names OpenAI Swarm and Microsoft AutoGen as pushing "the wrong way". [Established, opinion] — [Cognition, Jun 12, 2025](https://cognition.ai/blog/dont-build-multi-agents)
- Anthropic, the next day: a multi-agent system (Opus 4 lead + Sonnet 4 subagents) "outperformed single-agent Claude Opus 4 by 90.2% on our internal research eval". The concession: "domains that require all agents to share the same context or involve many dependencies between agents are not a good fit … most coding tasks involve fewer truly parallelizable tasks than research, and LLM agents are not yet great at coordinating and delegating to other agents in real time." [Established] — [Anthropic multi-agent research, Jun 13, 2025](https://www.anthropic.com/engineering/multi-agent-research-system)
- Partial convergence: Cognition notes Claude Code subagents "never [do] work in parallel" and are "usually only tasked with answering a question, not writing any code". Anthropic's context-engineering post recommends sub-agents returning "condensed, distilled summary" (1,000–2,000 tokens) for context isolation. [Established] — [Cognition](https://cognition.ai/blog/dont-build-multi-agents); [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- OpenAI: "maximize a single agent's capabilities first". Split agents only on complex conditional logic or tool overload. [Proposed] — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Anthropic's later stance is mixed. The long-running harness post lists single vs multi-agent as an open question ("it's still unclear"). Its "two agents" differ only by initial prompt: "The system prompt, set of tools, and overall agent harness was otherwise identical". [Established] — [Anthropic Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents). The Mar 2026 post adopts planner/generator/evaluator and says separating doer from judge "proves to be a strong lever". [Established] — [Anthropic harness design](https://www.anthropic.com/research/harness-design-long-running-apps)
- Dynamic tools: LangChain surveys RAG over tool descriptions as a fix for tool overload. Manus tried dynamic loading and advises against mid-iteration tool changes (cache invalidation, schema confusion). [Established] — [LangChain Context Engineering](https://blog.langchain.com/context-engineering-for-agents/); [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Compaction vs alternatives: Anthropic calls compaction "the first lever" ([context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)) but says "compaction isn't sufficient" for multi-window coding ([Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). It used resets for Sonnet 4.5 and then dropped them for Opus 4.5/4.6 ([Managed Agents](https://www.anthropic.com/engineering/managed-agents); [harness design](https://www.anthropic.com/research/harness-design-long-running-apps)). Manus argues "any irreversible compression carries risk" and makes compression restorable ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)). Anthropic Managed Agents agrees that irreversible decisions "can lead to failures" and makes the session log the recoverable store. [Established]
- Errors in context: Manus says "leave the wrong turns in the context". Anthropic BEA stresses ground truth from the environment at each step. These do not conflict. A contrasting practice Manus criticizes is cleaning the trace and retrying. [Established] — [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Few-shot examples: Anthropic "continue[s] to strongly advise" diverse canonical examples ([context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Manus warns "Don't Get Few-Shotted", meaning uniform action-observation history causes mimicry ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)). [Synthesized] They address different things: prompt examples vs self-generated history.
- Frameworks: Anthropic suggests "start by using LLM APIs directly" and warns that frameworks obscure prompts ([BEA](https://www.anthropic.com/engineering/building-effective-agents)). LangChain and Temporal promote framework or runtime adoption. [Synthesized]
- Which harness is best: LangChain says the harness a model was post-trained with is not necessarily best, citing "Opus 4.6 in Claude Code scores far below Opus 4.6 in other harnesses" on Terminal Bench 2.0. [Established, claim; leaderboard not independently checked] — [LangChain Anatomy](https://blog.langchain.com/the-anatomy-of-an-agent-harness/)

### Inferences
- [Synthesized] The single vs multi-agent dispute narrows to one condition. Read-only, breadth-first, parallelizable work (research, search) favours isolated subagents. Write-heavy, interdependent work (coding) favours a single thread or strictly scoped, non-parallel subagents. Anthropic and Cognition both state this condition explicitly.

### Gaps
- No controlled third-party comparison of single vs multi-agent harnesses was found in this track.

## 6. Quantitative evidence

### Takeaway
Numbers exist, but almost all are vendor-internal evals, single anecdotal runs, or vendor benchmark runs without released configs. Treat them as design-claim support, not evidence. The most decision-relevant ones are Anthropic's multi-agent +90.2% and its "token usage explains 80% of variance" analysis, the Managed Agents TTFT reductions, and LangChain's harness-only Terminal Bench gain (52.8 → 66.5).

### Cited Findings
- Multi-agent (Opus 4 lead + Sonnet 4 subagents) +90.2% over single-agent Opus 4 on an internal research eval. [Vendor-internal number] — [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)
- BrowseComp analysis: three factors explain 95% of performance variance, and token usage alone explains 80% (others: number of tool calls, model choice). [Vendor-internal number] — [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)
- Cost: agents use about 4× the tokens of chat; multi-agent systems about 15×. [Vendor-internal number] — [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)
- Parallel subagents (3–5) plus parallel tool calls (3+) "cut research time by up to 90% for complex queries". A tool-description-rewriting agent gave a "40% decrease in task completion time". A prompt tweak moved success "from 30% to 80%" (illustrative). [Vendor-internal number] — [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)
- Decoupling brain from hands: "p50 TTFT dropped roughly 60% and p95 dropped over 90%". [Vendor-internal number] — [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- Harness-only change: deepagents-cli improved from 52.8 to 66.5 (+13.7 points) on Terminal Bench 2.0 (89 tasks), model fixed at gpt-5.2-codex, "Top 30 to Top 5". [Vendor-reported benchmark] — [LangChain Improving Deep Agents](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering)
- Single anecdotal runs: retro game maker, solo 20 min / $9 vs full harness 6 hr / $200 (">20x more expensive"; quality judged qualitatively). DAW build on the simplified harness: about 4 hr / $124. [Anecdotal, n=1] — [Anthropic harness design](https://www.anthropic.com/research/harness-design-long-running-apps)
- Tool descriptions: Sonnet 3.5 reached SOTA on SWE-bench Verified "after we made precise refinements to tool descriptions" (no delta given). Concise vs detailed responses: 72 vs 206 tokens. The Claude Code tool-output cap is 25,000 tokens. [Vendor claim] — [Anthropic Writing tools](https://www.anthropic.com/engineering/writing-tools-for-agents)
- Manus: input:output ratio about 100:1; cached vs uncached input cost 10x ($0.30 vs $3/MTok, Claude Sonnet pricing); about 50 tool calls per average task. [Vendor-reported operational figures] — [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Claude Code auto-compact at 95% of the context window. [Reported by a third party, not by Anthropic] — [LangChain Context Engineering](https://blog.langchain.com/context-engineering-for-agents/)
- Effective-harnesses post: no quantitative results. It says testing tools "dramatically improved performance" (qualitative). [Established absence] — [Anthropic Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- OpenAI guide: no quantitative evals of its patterns. The "15 vs 10 tools" figure is an anecdote. [Established absence] — [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- Cognition and Temporal: no quantitative evidence offered. [Established absence] — [Cognition](https://cognition.ai/blog/dont-build-multi-agents); [Temporal](https://temporal.io/blog/of-course-you-can-build-dynamic-ai-agents-with-temporal)

### Inferences
- [Inference] The +90.2% result confounds architecture with total compute: the same post attributes 80% of variance to token usage. It does not isolate "multi-agent" from "more tokens", and Cognition's critique is untouched by it.
- [Inference] LangChain's Terminal Bench result is the only one here that holds the model fixed and varies only the harness on a public benchmark. That makes it the closest available evidence that harness design matters, though it is still self-reported and single-vendor.

### Gaps
- No independent replication of any of the above was found.
- No vendor reports ablations per responsibility (e.g. the effect of compaction alone or the memory tool alone) with numbers. Anthropic's harness-design post describes one-at-a-time component removal only qualitatively.
