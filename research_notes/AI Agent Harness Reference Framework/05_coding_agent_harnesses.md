## Q1. Architecture per system, the responsibility × system matrix, and open-source status

### Takeaway
By November 2026 all four systems share a common harness shape. Each has a terminal or IDE agent loop, a headless mode, and a cloud or background execution path. Each reads markdown instruction files (all four accept AGENTS.md), compacts context automatically, runs subagents, and offers MCP, hooks, skills, custom agents and an SDK.
They differ mainly in four places:
- **Where execution happens.** Claude Code and Codex use OS sandboxes locally. Copilot runs on GitHub Actions runners or GitHub cloud sandboxes behind a firewall. OpenCode has no documented sandbox.
- **Openness.** Codex CLI is Apache-2.0 and OpenCode is MIT. Claude Code and Copilot CLI are proprietary.
- **Model breadth.** OpenCode and Copilot are multi-vendor. Codex has an OpenAI default plus custom and local providers. Claude Code is Anthropic-first, but leaderboard runs show it can drive third-party models.
- **Permission model.** Covered under the Control row and in Q2.

### Cited Findings (beyond the matrix)
- Codex documents sandbox mode, meaning "what Codex can do technically", and approval policy, meaning "when Codex must ask", as two separate axes. Local Codex defaults to "no network access and write permissions limited to the active workspace". **[E]** [Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security.md)
- Claude Code's sandbox network starts with "allowed domains … empty", and traffic is forced through a local proxy. `curl --noproxy` fails because "the command has no route around the sandbox proxy". **[E]** [Sandboxing](https://code.claude.com/docs/en/sandboxing.md)
- GitHub compares its two cloud environment types. Cloud-sandbox sessions "can be shared and resumed across clients" and "can span across repositories". Actions sessions are web-only, single-repo, and support custom compute and self-hosted runners. **[E]** [About coding agent](https://docs.github.com/api/article/body?pathname=/en/copilot/concepts/agents/coding-agent/about-coding-agent)
- A source-code study of 11 harnesses pinned to July 2026 found the following. It includes Claude Code, Codex CLI and OpenCode but not Copilot. **[E]** [Barbaste et al., arXiv 2609.00006](https://arxiv.org/pdf/2609.00006)
  - No harness imports a general agent framework.
  - None retrieves code with vector embeddings. All rely on ripgrep, tree-sitter, glob and markdown context files.
  - SKILL.md skills appear in 9 of 11 systems and MCP in 8 of 11.
  - OpenCode is "the most-starred dedicated coding agent on GitHub (~184k stars)".
  - The paper lists Copilot CLI as closed-source (✗).

### Inferences
- **[S]** The four harnesses have converged on the same extensibility vocabulary: AGENTS.md, MCP, SKILL.md skills, hooks, custom agents, subagents and auto-compaction. GitHub and OpenCode both read Claude Code's CLAUDE.md files and skills directly. Feature-checklist differences between the systems are therefore now small.
- **[S]** The architectural differences that remain are in execution isolation, openness and model portability:
  - **Execution isolation.** Codex sandboxes by default. Claude Code's sandbox is opt-in, with an optional classifier-based auto mode. Copilot gets isolation from a VM or runner plus a firewall. OpenCode documents no sandbox.
  - **Openness.** See Q1 versions.
  - **Model portability.** See the Model choice row.
- **[P]** For the reference framework, Copilot is best treated as a *platform with multiple harnesses*. Its "cloud agent" is an execution and orchestration layer on Actions or sandboxes, and VS Code can host the Claude or Codex harness inside it. It should not be modelled as a single agent loop.

### Gaps
- **[Unreachable]** Copilot's agent-mode internals are not described: loop design, tool schemas, compaction strategy. Whether the VS Code Copilot Chat extension source is open was **not verified in this run**; I recall an MIT open-sourcing from 2025, but this is unverified and should be checked at github.com/microsoft/vscode-copilot-chat.
- The full Claude Code hooks, skills and plugins pages were not read individually. Their existence is established from the docs index (llms.txt), and the details come from the changelog and other pages.
- OpenCode's sandbox status rests on its absence from the docs. The source in anomalyco/opencode was not inspected because GitHub API and repo access was not enabled.

## Q2. Test of the hypothesis "Copilot is less capable as an agent harness than Claude Code, Codex or OpenCode"

### Takeaway
**The evidence is insufficient to confirm the hypothesis, and the documented feature set partly contradicts it.**
- On documented capabilities, Copilot now matches the others on nearly every matrix row. It leads on cloud and execution-environment options (Actions runners, self-hosted and Windows runners, cross-client sandboxes) and on model breadth.
- It has specific, vendor-documented gaps:
  - The cloud agent supports only a subset of hooks.
  - The firewall covers only Bash-tool processes and can be bypassed.
  - Actions-based sessions are web-only and limited to one repository.
  - There is no documented OS-level local sandbox in the CLI. Only tool approvals and allow/deny flags are documented, which is **Inference** from the CLI doc.
- **No independent harness-level benchmark found includes Copilot.** Terminal-Bench 4.1 and the independent papers and reviews compare Claude Code, Codex, OpenCode and others, not Copilot. Performance-based claims about Copilot as a harness therefore cannot be tested with current public evidence.

### Cited Findings
- **Terminal-Bench 4.1 official leaderboard.** The URL tbench.ai/leaderboard/terminal-bench/2.0 now serves the TB 4.1 board, which was updated 2026-11-11 and has 35 rows. **[E]** [tbench.ai leaderboard](https://www.tbench.ai/leaderboard/terminal-bench/2.0)
  - Harnesses present: Claude Code, Codex, xAI Grok Build, mini-SWE-agent and Meta Muse Code. **No OpenCode or Copilot entries.**
  - Top rows:
    - Claude Code + Opus 5.5 (max effort): 65.8% ± 3.1, n=330
    - Claude Code + Sonnet 5.5: 63.9%
    - Codex + GPT-6.1 Sol: 60.9%
    - Codex + GPT-6 Astra: 60.3%
  - Claude Code also appears with non-Anthropic models: GLM-5.3 at 41.2% and Qwen3.8-Max at 27.0%.
  - Every top entry is a vendor's harness paired with the same vendor's model. The rows record "Agent Org" equal to the vendor. **These are best treated as vendor-associated submissions.** The leaderboard does not show who ran them (**Inference**).
- **SWE-Chain (independent, CUHK et al., May 2026).** It ran Codex CLI 0.121–0.128, Claude Code 2.1.113–2.1.126 and OpenCode 1.14.x across 9 agent-model configurations. Copilot was not included. **[E]** [arXiv 2605.14415](https://arxiv.org/pdf/2605.14415)
  - Claude-Opus-4.7 in Claude Code led with 60.8% resolving and 68.5% F1.
  - "GPT-5.4 performs better with Codex than OpenCode". The same model gave different results in different harnesses.
- **TestEvo-Bench (Waterloo/Google, Jul 2026).** It compared the Claude Code, Gemini CLI and SWE-Agent harnesses, reaching up to 77.5% on test generation. Copilot was not included. **[E]** [arXiv 2607.02469](https://arxiv.org/pdf/2607.02469)
- **Tensorlake 14-day test (independent blog, 30 tasks, same model DeepSeek V4 Flash).** Copilot was not tested. The sample is small and comes from a vendor-adjacent blog, so it is weak evidence. **[E]** [Tensorlake](https://www.tensorlake.ai/blog/best-ai-coding-agents-2026)
  - Pi: 20/30
  - Claude Code: 16/30 at $0.195 per success
  - Codex: 16/30 at $0.081 per success, with median 245 s against Claude Code's 123 s
  - OpenCode: 14/30
- **Databricks same-model test, reported secondhand by Tensorlake.** On Opus 4.8, tokens per task were 742k for Claude Code, 1.235M for Codex and 237k for Pi, with the "same success rate". **[E that Tensorlake reports it; primary Databricks source not read → Unreachable/secondhand]** [Tensorlake](https://www.tensorlake.ai/blog/best-ai-coding-agents-2026)
- **OpenBench (independent GitHub project).** It holds the model fixed and varies the harness across codex, pi, opencode, cursor, devin and open-model claude. Copilot is not included. The README reports that "correctness saturates for frontier harnesses on repo-authored tasks". **[E]** [OpenBench README](https://raw.githubusercontent.com/minghinmatthewlam/openbench/main/README.md)
- **The harness matters as much as the model.**
  - A position paper argues that harness-induced variance can exceed model-induced variance, including cases where model rankings reverse. It says leaderboards that do not disclose the harness are "incomplete and potentially misleading". **[E]** [Zhang et al., arXiv 2605.23950](https://arxiv.org/pdf/2605.23950)
  - A controlled ablation study (176 settings, SWE-Bench Verified and Terminal-Bench 2.1) found that context management matters most under tight context budgets. Bash-only action spaces suit bash-capable models at lower cost. **[E]** [Fan et al., arXiv 2609.20804](https://arxiv.org/pdf/2609.20804)
- **Copilot's own harness-plurality signal.** VS Code lets users "work with the Copilot, Claude, or Codex agent harness". **[E]** [VS Code agents overview](https://code.visualstudio.com/docs/copilot/agents/overview)
- **Vendor claim only.** GitHub says "initial performance testing" shows cloud-sandbox sessions completing "faster on average" than Actions-based sessions. **[E, vendor claim]** [About coding agent](https://docs.github.com/api/article/body?pathname=/en/copilot/concepts/agents/coding-agent/about-coding-agent)

### Inferences
- **Verdict [S]:** *Not supported as stated; the evidence is insufficient on performance.*
  - **Feature parity.** The documented feature surface no longer supports "less capable" across the board.
  - **Where Copilot is narrower.** Hook coverage on the cloud agent and the firewall scope are documented limits. Local CLI isolation looks weaker than Codex's default OS sandbox or Claude Code's optional sandbox (**Inference**).
  - **Where Copilot is broader.** It offers more execution environments and more models, and it can host rival harnesses.
  - **Missing evidence.** There is no public same-model, harness-varied evaluation that includes Copilot, so a performance gap can be neither shown nor ruled out.
- **[Inference]** Copilot's absence from Terminal-Bench and the academic harness studies is itself a fact worth reporting. It means claims of Copilot's inferiority rest on anecdote or on older (2025) comparisons, not on current controlled data.
- **[P]** Experiment that would settle the question: run Copilot CLI (`copilot -p --allow-all-tools`), Claude Code, Codex and OpenCode with one model they all support.
